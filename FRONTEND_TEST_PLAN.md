# FRONTEND_TEST_PLAN.md

## 1) Preconditions
1. Запусти backend API и убедись, что Swagger доступен по адресу `http://localhost:5107/swagger`.
2. Открой фронтенд в браузере.
3. Открой DevTools:
   - Вкладка Network
   - Вкладка Application/Storage (для проверки токенов в localStorage)

## 2) Login Flow (JWT + UI state)
1. Перейди на `/login`.
2. Введи валидные данные:
   - Username: `superadmin`
   - Password: `Merc2024!`
3. Нажми **Sign In**.
4. Проверь:
   - UI редиректит на `/` (каталог).
   - В Network `POST /api/auth/login` возвращает `200`.
   - В ответе есть `accessToken`, `refreshToken`.
   - В localStorage появились оба токена.
5. Обнови страницу браузера.
6. Проверь, что пользователь остался залогинен (нет редиректа на login).

## 3) Unauthorized Handling
1. Удали или испорть `ws.accessToken` в localStorage вручную.
2. Перейди на защищённую страницу (`/user-profile` или `/admin/users`).
3. Проверь:
   - API возвращает `401`.
   - UI показывает “not authorized / please login” (не пустая страница).
   - Можно перейти на `/login` и снова войти.

## 4) Catalog Loading
1. Открой `/`.
2. Проверь первый запрос каталога:
   - `GET /api/products/paged?page=1&pageSize=20...`
   - Статус `200`.
3. Проверь, что карточки продуктов отображают реальные данные из API (не только заглушки):
   - Название
   - Цена/кредиты
   - Ссылка на детали
4. Проверь, что при медленном интернете появляется индикатор загрузки.

## 5) Pagination
1. На странице каталога нажми **Next**.
2. Проверь:
   - запрос увеличивает page (`page=2`)
   - API возвращает `200`
   - список товаров меняется
3. Нажми **Prev**.
4. Проверь:
   - запрос возвращает предыдущую страницу
   - первая страница возвращается корректно
5. Крайний случай:
   - На первой странице кнопка Prev неактивна.

## 6) Search
1. Введи текст поиска (например: `Dell` или `MacBook`).
2. Запусти поиск (кнопка или Enter).
3. Проверь:
   - запрос содержит `search=<значение>`
   - статус `200`
   - список отфильтрован
4. Очисти поиск.
5. Проверь, что возвращается полный список.

## 7) Product Details
1. В каталоге нажми **View** на карточке товара.
2. Проверь, что роут меняется на `/product/{id}`.
3. Проверь, что страница загружает детали товара из API:
   - название
   - описание
   - цена
   - наличие
4. Используй ссылку “Back”, чтобы вернуться в каталог — не должно быть ошибок.

## 8) Admin/User Pages Guarding
1. Будучи залогинен как admin, перейди на `/admin/users`.
2. Проверь, что API возвращает `200` и таблица пользователей отображается.
3. Выйди из аккаунта (или удали токены), снова зайди на `/admin/users`.
4. Проверь, что появляется “not authorized” (а не пустая страница).

## 9) Error UX
1. Останови backend API.
2. Перезагрузи страницу каталога.
3. Проверь:
   - появляется дружелюбное сообщение об ошибке
   - нет бесконечного спиннера
4. Запусти API снова и повтори действие.
5. Проверь, что UI восстанавливается без полной перезагрузки.

## 10) Regression Smoke
1. Login → Catalog → Search → Pagination → Product details → Back → Profile → Logout.
2. Убедись, что в консоли браузера нет необработанных ошибок.
3. Убедись, что после переходов не происходит дублирующихся API-запросов.
